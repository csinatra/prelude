| 2026-08-03 | Retrieval unit → notebook SUMMARY only; two-level code-chunk retrieval collapsed to a flat retrieve over notebook_summaries. Probe (analysis/probe_representation.py; 6 notebooks across NLP/tabular/vision) showed the rich whole-notebook summary already carries the transferable content (exact hyperparameters, feature recipes, validation schemes, distinctive techniques); curated code cells added mostly verbatim implementation + large lookup tables at 2–10× the summary's tokens, and by leave-one-out that verbatim code is always from a DIFFERENT competition — the least transferable part. Resolves four issues at once: code-cell signal density (boilerplate noise), the NL-problem↔code retrieval modality gap, cleaner B/C parity, system complexity; also production-faithful (summary/abstract-indexed retrieval is the standard RAG-over-code pattern). **Parity redefined to DISTINCT documents reasoned over**: B draws BASELINE_N_NOTEBOOKS in one flat pass; C's 3 directed stages retrieve independently (duplicates RETAINED — each stage reasons over its own top-N, no reasoning-time dedup, so a notebook relevant to multiple stages is used by each) with cross-stage top-up (retrieve_with_topup: each repeat backfilled by the next-best unseen doc) so every stage contributes STAGE_N distinct → 3×STAGE_N = BASELINE_N distinct. Token asymmetry from retained repeats is logged, not equalized. practitioner_knowledge stays ingested but unqueried at spec time (door open to curated-cell grounding later). The single-upfront-pool alternative was rejected: it tests directed *synthesis* over flat retrieval — a different question than directed *retrieval*, which is H1's mechanism. | 2026-08-03 | Embedding model: `voyage-code-3` → `voyage-4-large`.
